# AI Reference — GUM Self-Contained Configuration Bundle

[Versão em português](./pacote-configuracao-autocontido.md)

> Format for transporting a GM Screen or world-status configuration together with its dependent Items.
>
> Implemented as `gum-configuration-bundle`, version `1`.

## Structure

```json
{
  "format": "gum-configuration-bundle",
  "version": 1,
  "id": "stable-identifier",
  "name": "Display name",
  "kind": "gm-screen",
  "configuration": {},
  "documents": {},
  "portability": {
    "complete": true,
    "unresolvedReferences": [],
    "unsupportedReferences": [],
    "externalAssets": [],
    "systemVersion": "1.4.4-beta",
    "foundryVersion": "13"
  }
}
```

`kind` accepts `gm-screen` or `world-statuses`. Keep `id` stable across reimports. Documents are synchronized into an Item compendium before the configuration is applied. IDs, folders, and rollback use the same guarantees as the [self-contained Item bundle](./self-contained-item-bundle.md).

`portability` is generated by the exporter. It records references that could not be embedded, unsupported document types, external image paths, and source versions. An AI-authored file may omit this object; it is diagnostic metadata rather than configuration.

## GM Screen

With `kind: "gm-screen"`, each `group.items` entry may be an external UUID or a local reference:

```json
{
  "items": [
    { "itemRef": "fog" },
    { "itemRef": "darkness-penalty" }
  ]
}
```

`itemRef` must target an `effect` or `gm_modifier` Item in `documents`. A `gm_modifier` may also use `effectRef` in regular Item effect links such as `passiveEffects` and `activationEffects`. Exports automatically include these indirect effects.

## World statuses

With `kind: "world-statuses"`, local references appear in `effectUuids`:

```json
{
  "version": 2,
  "initialized": true,
  "bindingsMigrated": true,
  "statuses": [
    {
      "id": "stunned",
      "name": "Stunned",
      "img": "systems/gum/icons/status/stunned.png",
      "effectUuids": [
        { "effectRef": "stunned-effect" }
      ],
      "legacyRuleUuids": [],
      "stackMode": "refresh",
      "stackLimit": 1,
      "removeOnStatusOff": true,
      "custom": false
    }
  ]
}
```

`statuses` is the complete authoritative list, and its array order is the display order. An initialized configuration with `statuses: []` intentionally represents a world with no configured statuses. System defaults are only an initial reference or a restore option; they may be removed and do not reappear automatically.

The auxiliary form `effectRefs: ["stunned-effect"]` is also accepted. Each target must be an `effect` Item in `documents`. Multiple statuses may share one key, creating the Effect Item only once.

## Compatibility and behavior

- The GM Screen and world-status exporters generate this format automatically.
- Legacy JSON files containing only configuration data remain supported.
- External UUIDs without an embedded document are preserved. They remain dependent on content already installed in the destination world.
- Import shows a preview before writing and offers three modes: `Add only`, `Merge and update`, and `Replace all`.
- `Add only` preserves existing options while collecting new groups, links, and statuses. It does not disable statuses already available in the world.
- `Merge and update` is the default: imported data updates entries with the same ID, links are combined without duplication, and local-only entries remain.
- `Replace all` treats the imported configuration as complete. For statuses, the imported list exactly replaces the world list, including when it is empty. Effects already applied to actors are not deleted.
- A configuration failure rolls back Items and folders created or updated by the operation.
- Images remain Foundry paths; image files are not embedded in the JSON.
